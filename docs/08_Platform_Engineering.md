## 1. Architecture Philosophy: The Robust Modular Monolith

DERMA-GUARD is built as a **modular monolith** with an asynchronous background worker system. This design balances simplicity, speed of iteration, strict consistency, and enterprise-grade auditability.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        NEXT.JS / REACT FRONTEND                        │
│   Case Intake │ Evidence Review │ Conformal Visualizer │ Stress Lab   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ HTTPS / REST (Typed OpenAPI)
┌───────────────────────────────────▼────────────────────────────────────┐
│                       FASTAPI BACKEND SERVICE                          │
│   Auth & RBAC  │ Case Controller │ Assessment Engine │ Audit Middleware│
└───────────┬───────────────────────┬─────────────────────────┬──────────┘
            │ SQL                   │ Enqueue Jobs            │ S3 API
┌───────────▼───────────┐ ┌─────────▼─────────┐ ┌─────────────▼──────────┐
│  POSTGRESQL + PGVECTOR │ │  REDIS MESSAGE   │ │     OBJECT STORAGE     │
│   Immutable Audit     │ │      BROKER       │ │   (Local / MinIO)      │
│   Case & Model State  │ └─────────┬─────────┘ │   Dermoscopy & Clinical│
│   RAG Vector Chunks   │           │ Pull Jobs └────────────────────────┘
└───────────────────────┘ ┌─────────▼─────────┐
                          │   CELERY / RQ     │
                          │   WORKER DAEMON   │
                          │ PyTorch Inference │
                          │ EADE Optimization │
                          │ DERMA-STRESS Run  │
                          └───────────────────┘
```

## 2. Technology Stack Overview

| Layer | Selected Technology | Architecture Rationale |
|---|---|---|
| **Frontend** | Next.js 14, React, TypeScript, Tailwind CSS | Type-safe UI, responsive clinical dashboard, fast graph rendering. |
| **Backend API** | Python 3.11, FastAPI, Pydantic v2 | High-throughput async framework with automatic OpenAPI documentation. |
| **Relational & Vector DB** | PostgreSQL 16 + `pgvector` extension | Single unified database for relational audit records and vector embeddings. |
| **Task Queue & Broker** | Redis 7 + Celery / RQ | Decouples heavy neural network forward passes from HTTP request lifecycle. |
| **Object Storage** | MinIO (or Local POSIX in dev) | S3-compatible, immutable content-addressed storage for high-resolution TIFF/JPG. |
| **Machine Learning Core** | PyTorch, `timm`, `torchvision`, Scikit-Learn | GPU-accelerated deep vision backbones (ConvNeXt, EfficientNet) and tabular GBMs. |
| **Conformal Calibration** | Custom In-house Module (~150 LOC) | Minimal, auditable, fully transparent implementation of Learn-Then-Test. |

## 3. Database Schema (PostgreSQL DDL)

The data model is strictly append-only for medical auditability. Records are never deleted or silently overwritten.

```sql
-- 1. Patient Cases
CREATE TABLE patient_cases (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() NOT NULL,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() NOT NULL,
    status VARCHAR(32) NOT NULL, -- DRAFT, ASSESSING, COMPLETED, DEFERRED, REVIEWED
    created_by VARCHAR(64) NOT NULL,
    permitted_metadata JSONB NOT NULL DEFAULT '{}'::jsonb
);

-- 2. Evidence Assets (Uploaded files and extracted signals)
CREATE TABLE evidence_assets (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    case_id UUID REFERENCES patient_cases(id) ON DELETE CASCADE,
    asset_type VARCHAR(32) NOT NULL, -- clinical, dermoscopy, metadata, text
    storage_key VARCHAR(255) NOT NULL,
    content_hash VARCHAR(64) NOT NULL, -- SHA-256 for cryptographic integrity
    quality_status VARCHAR(32) NOT NULL, -- ACCEPTABLE, DEGRADED, REJECTED
    quality_scores JSONB NOT NULL DEFAULT '{}'::jsonb,
    uploaded_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() NOT NULL
);

-- 3. Evidence Snapshots (Immutable point-in-time state of a case)
CREATE TABLE evidence_snapshots (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    case_id UUID REFERENCES patient_cases(id) ON DELETE CASCADE,
    asset_ids UUID[] NOT NULL,
    missingness_record JSONB NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() NOT NULL
);

-- 4. Clinical Assessments (System decisions generated by EADE)
CREATE TABLE assessments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    case_id UUID REFERENCES patient_cases(id) ON DELETE CASCADE,
    snapshot_id UUID REFERENCES evidence_snapshots(id),
    policy_version VARCHAR(32) NOT NULL,
    calibration_version VARCHAR(32) NOT NULL,
    cost_matrix_version VARCHAR(32) NOT NULL,
    ltt_threshold FLOAT NOT NULL,
    action VARCHAR(16) NOT NULL, -- PROCEED, ACQUIRE, DEFER
    reason_codes TEXT[] NOT NULL,
    conformal_set TEXT[] NOT NULL,
    expected_losses JSONB NOT NULL, -- {proceed: 0.12, acquire: 0.35, defer: 0.50}
    result_summary JSONB NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() NOT NULL
);

-- 5. Deep Model Runs (Individual forward pass metrics)
CREATE TABLE model_runs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    assessment_id UUID REFERENCES assessments(id) ON DELETE CASCADE,
    model_name VARCHAR(64) NOT NULL,
    model_version VARCHAR(32) NOT NULL,
    ensemble_seed INT NOT NULL,
    temperature FLOAT NOT NULL,
    output_scores JSONB NOT NULL, -- Calibrated posterior probabilities
    entropy FLOAT NOT NULL,
    mutual_information FLOAT NOT NULL,
    ood_score FLOAT NOT NULL,
    runtime_ms INT NOT NULL,
    status VARCHAR(32) NOT NULL
);

-- 6. Audit Events (Tamper-evident system activity log)
CREATE TABLE audit_events (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    case_id UUID REFERENCES patient_cases(id),
    actor_type VARCHAR(32) NOT NULL, -- USER, WORKER, SYSTEM
    actor_id VARCHAR(64) NOT NULL,
    event_type VARCHAR(64) NOT NULL, -- CASE_CREATED, ASSET_UPLOADED, DECISION_COMPUTED, REVIEW_LOGGED
    event_payload JSONB NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW() NOT NULL
);
```

## 4. Complete REST API Specification

All endpoints are prefixed with `/api/v1` and require Bearer token authorization.

### 4.1 Case Intake & Asset Management

#### `POST /api/cases`
Creates a new patient case container.
```json
// Request Body
{
  "permitted_metadata": {
    "age_bin": "50-54",
    "sex": "female",
    "anatomical_site": "torso",
    "skin_tone_level": 3
  }
}
// Response 201 Created
{
  "case_id": "8f3b2160-b6f1-46ab-a29d-478648b26410",
  "status": "DRAFT",
  "created_at": "2026-10-11T08:00:00Z"
}
```

#### `POST /api/cases/{case_id}/assets`
Uploads a binary image asset (`multipart/form-data`). Automatically triggers SHA-256 hashing and quality scoring.
- Form fields: `asset_type` (`clinical` | `dermoscopy`), `file` (Binary image).
- Response: `asset_id`, `content_hash`, `quality_status` (`ACCEPTABLE` | `DEGRADED`), `laplacian_variance`.

#### `POST /api/cases/{case_id}/assessments`
Enqueues an asynchronous assessment pipeline run for the latest evidence snapshot.
- Returns `202 Accepted` with `job_id` and idempotency key.

#### `GET /api/assessments/{assessment_id}`
Returns complete clinical decision record, conformal set, calibrated probabilities, and expected loss breakdown:
```json
{
  "assessment_id": "31fa6b12-073c-4a3d-b4ef-f7d98341147a",
  "case_id": "8f3b2160-b6f1-46ab-a29d-478648b26410",
  "action": "ACQUIRE",
  "reason_codes": [
    "REASON_CONFORMAL_SET_MIXED",
    "REASON_ACQUIRE_EXPECTED_BENEFIT_EXCEEDS_COST"
  ],
  "conformal_set": ["melanoma", "nevus"],
  "expected_losses": {
    "proceed": 0.485,
    "acquire": 0.231,
    "defer": 0.500
  },
  "calibrated_probabilities": {
    "melanoma": 0.42,
    "nevus": 0.51,
    "basal_cell_carcinoma": 0.04,
    "seborrheic_keratosis": 0.03
  },
  "uncertainty": {
    "predictive_entropy": 0.942,
    "mutual_information": 0.184,
    "ood_mahalanobis": 1.24
  },
  "policy_metadata": {
    "policy_version": "v2.0-expected-loss",
    "calibration_alpha": 0.05,
    "confidence_delta": 0.10,
    "ltt_threshold": 0.38
  }
}
```

#### `GET /api/cases/{case_id}/timeline`
Returns chronological audit history of all case interactions: creation, uploads, assessments, and human specialist notes.

#### `POST /api/cases/{case_id}/reviews`
Records dermatologist specialist review notes, confirmed diagnosis, and closes case.

#### `POST /api/experiments`
Dispatches a DERMA-STRESS benchmark run across designated split hash and failure family.

## 5. Security, Safeguards, and Regulatory Compliance

```
┌────────────────────────────────────────────────────────────────────────┐
│                        SAFETY AND PRIVACY GATES                        │
├────────────────────────────────────────────────────────────────────────┤
│ 1. Zero PHI Storage: Direct patient identifiers (names, MRNs, phone   │
│    numbers) are strictly stripped before reaching the database.        │
│ 2. Cryptographic Content Hashing: Every uploaded image is hashed with  │
│    SHA-256 upon ingestion; changes to bytes invalidate the snapshot.   │
│ 3. Explicit Medical Disclaimers: UI and API headers declare:           │
│    "RESEARCH PROTOTYPE ONLY - NOT FOR DIRECT CLINICAL USE".            │
│ 4. Fallback on LLM Outages: RAG and text extractors use deterministic  │
│    regex fallback rules if external LLM inference times out.           │
└────────────────────────────────────────────────────────────────────────┘
```

## 6. Verification and Acceptance Testing

The platform enforces a four-tier testing hierarchy before any model run:
1. **Unit Tests (`pytest tests/unit`):**
   - Cost matrix loss formulation validity.
   - Conformal set construction and empty-set checks.
   - LTT threshold monotonicity on synthetic calibration arrays.
2. **Integration Tests (`pytest tests/integration`):**
   - End-to-end upload $\to$ Redis job enqueued $\to$ worker processes $\to$ assessment saved in DB.
   - Idempotency verification under duplicate submission.
3. **Research Integrity Tests (`pytest tests/research`):**
   - Leak-free verification: Confirm intersection between train, val, cal, and test patient/lesion IDs is null.
   - Guarantee sanity: On synthetic i.i.d. draws, empirical risk satisfies $\hat{\mathcal{R}} \le \alpha$ in $\ge (1 - \delta)$ repetitions.
4. **Resilience Tests:**
   - Worker crash simulation: Ensure killed worker transitions job to `FAILED_RETRIEVABLE` without data corruption.
